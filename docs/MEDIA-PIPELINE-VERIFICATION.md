# 生图滚动流水线：实施与验收

日期：2026-10-22。范围为共享执行脚本、宿主接入示例及 mock；真实生成、上传和当前项目批次均未执行或改写。

## 三轮实施

1. **存储与计时**：在原存储模块增加 v2 执行记录；prepare 合并认领、请求和参考核对，capture 同步保存小回执，finalize 合并复制、哈希验证和结果登记。复用原图片保存及回执过滤逻辑。保留 v1 存储和旧回调入口。
2. **阶段与恢复**：控制状态采用追加版本文件，记录收到、观察与生效时间；提交闸门拒绝过期准备结果。成功、已返回、提交未明、失败分别恢复；未知任务与被拒绝保存不自动重试。输入与尝试身份独立于 Prompt 文本。
3. **滚动调度**：生成默认4、收尾1、待收尾4。依赖在认领前筛选，优先链头；回执持久化即释放生成槽位，补位提交优先于派发复制。LibTV 复用已有素材流水线，增加慢素材隔离与第五项补位测试，没有修改其远端工具协议。

接口与可执行宿主示例见[共用媒体流程](../storyboard-workbench/references/media-execution.md)。主入口仍为 runMediaBatch，传 prepare/capture/finalize 进入流水线；createGenerationPipelineStore 提供新存储、控制和批末汇总。generation.mjs 同步重导出。

## 切换与回退

- 新批次加载更新后的 host-source 并使用新存储入口。已运行会话中已加载的旧函数不会被热替换；下个新批次须重新加载入口。
- 旧批次保持原格式，不原位迁移；新输入、新阶段和新版本使用新目录。现有图片、S11 原图、拒绝记录及 Excel 不由本次维护更新。
- 回退先 setControl 暂停、等待 observed/effective 确认，再核对在途和回执；旧入口只能继续旧合同批次，不把 v2 目录交给 v1 重开。

## 2026-10-27 对抗性审查后的修复

本轮仅修改共享代码、合同、接入示例与离线测试，保留已有未提交改动及原批次数据，没有触发真实生图、MCP 提交或付费调用。

- **挂起后的交付**：imagegen 的 execute 默认等待上限300秒，本地桥接默认30秒；LibTV 提交、查询、交付请求与可选下载默认120秒，可显式配置。到期停止新增派发，保留原任务身份，仍汇总已保存结果。等待结束不伪造成远端返回或取消；晚到工具响应不续写本轮状态。
- **未明容量与恢复**：新旧批次均先读取恢复快照，claimed/submitting/submitted/pending/unknown 不作为空槽。v2 超时追加 wait-expired 事件，v1 超时追加独立观察文件，均不占用真实结果终态；取得同一原任务的真实回执后可恢复保存，不另提生成。旧自定义回调须传 snapshot 或 initialStates，才能获得跨运行保护。
- **收尾死锁**：恢复任务进入收尾等待前释放 preparing，待收尾队列达到上限仍可排空。覆盖并发4/8和待收尾上限1/4，而不是只检查默认配置。
- **能力适配**：新增有证据和时间的能力观察，实际媒体入口拒绝明确不支持的能力；旧 run 与未知能力保持兼容。规则正文可按显式字符预算分块完整读取，默认输出不变。runtime 修订允许追加失败解决记录，保留失败历史，不消耗创作修复次数或作废未变更镜头评分。

回归覆盖永不返回与晚到调用、部分成功交付、重启零重复提交、超时后原回执恢复、满队列排空、无 import 宿主源码、能力拒绝早于副作用、旧合同及运行记录修订。测试只使用本地假接口和独立临时文件。
