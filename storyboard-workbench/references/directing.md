# 共用导演方法

方法参考 [DirectorSKILL / cinematic-director](https://github.com/wuwangzhang1216/DirectorSKILL)，原作者 wangzhang-wu，MIT；归属见[许可证](director-license.txt)。这是本项目适配，不要求安装上游全套流程。新 Excel 数据与失败处理按[工作流](visual-workflow.md)；旧工作台字段写入只在[旧入口](legacy-workbench.md)生效。

## 全片到单镜

先以原稿确认每镜的画面目的：交代空间、交代关系、准备期待、揭示信息、反应或升级。商业脚本按可见信息理解，不扩展受众或营销任务，不强加潜台词。原稿缺少镜头作用时记录导演建议，不静默删除原镜。

建立或复用稳定人物、场景、道具 ID，消解同名与别名；原文事实、用户确认、导演补全、未知项分别记录。关键缺口或冲突保留问题；已获授权的普通拍法、虚构造型与非关键布景统一设计并沿用。不得根据中文推定族裔，不能把导演建议当实拍数据或用户确认。

在场景信息和场景 Prompt 之间完成[场景美术与陈设设计](scene-art-direction.md)，具体设计空间使用者与功能、核心布局、陈设层次、使用痕迹、材质和画面取舍，并检查已有正负描述的真实冲突。保存同一场景的共用设定后，镜头仅选择当前机位可见部分；必要功能限制不因增加装饰而失效，已确认布置的修订保留历史并核对受影响镜头。

先规划人物位置、进入状态、动作阶段和结束状态，再确定镜头位置与景别。核对相邻切点及跨场景返回的身份、服装、道具、视线、轴线、门窗和光源。世界中的座位与灯位不因换机位改变；画面左右是当前机位的关系，不能当作地理方位。空间依据不足时不镜像房间，不伪造左右。

视频任务在全片规划时按[画面衔接与首尾帧设计](video-workflow.md#画面衔接与首尾帧设计)先确定连接关系与承接依据，再写各镜正文；镜头内的连续变化与相邻镜头的剪辑分别检查，硬切、静止反应和明确时空跳转均可按叙事目的采用。

静帧选择一个有意义的时刻：动作将开始、刚完成、关系变化或信息揭示。先后发生的动作、运镜及结束状态另列。快切与表情首末帧绑定源镜号，定格明确复用来源，不把必要顺序帧写成互斥候选或重复累计时长。用户时长要求优先，调整时保留源映射和理由。

## 人物、关系与摄影

按实际出镜人物逐人记录必要可见特征、位置、朝向、姿态、表情、视线、手部及持物；道具写明所有者、位置与状态，关系区分视线、接触、遮挡和同框。无人、不见脸或其他不适用项按合同记录原因，不强造人物，不把全片人物机械填进每个镜头。

完整人设留在人物资产，不复制或隐藏追加到每镜正文。人物模型指代按[真实参考规则](prompt-language.md#人物指代内部身份与模型正文)：实际已确认图用准确绑定的引用，没有图用本镜必要可见特征及清楚称呼。内部名字、ID 与文字档案都不代表模型已经认识该身份。

景别、机位、取景与构图服务于必须读清的信息。焦距、光圈、焦点和清晰范围独立规划并自然写入新版正文；用户未指定时记录导演建议与画幅基准，不编造相机品牌型号、照度、ISO或实拍曝光。前后不同距离的多人是否清楚不能只由一个 f/值保证。旧 concise-v1 的摄影显示范围只按旧入口，不覆盖新版摄影要求。

多人镜明确谁做什么、看谁、拿什么以及谁必须同时可见。生活喜剧先让观众理解正常状态，再呈现可读反差；双人互动和反应可同时出现，单人反应须承担实际信息。用眉眼、肩膀、手和视线描述表演，不堆叠情绪词，景深要让关键人物和物件可读。

手机照片等画中画区分外层摄影机与照片内部视角；照片是静止的。身份与拍摄失误分开，准确 UI/文字如需后期合成应记录，不承诺一次生成精确文字。

## 一案、调整与核对

默认每镜一案。用户要求调整时，候选应有明确构图、机位或信息差异，例如双人中景保留互动、过肩突出被观察者、手部特写揭示道具。候选仍保留同一源事件和关键事实，不为凑数量旋转几度或换形容词；查看候选不代表采用，应用后才更新总表。

先完成结构与全片状态，再按[自然表达规则](prompt-language.md)组织一稿。维度是核查依据，不是 Prompt 固定段落；不要先写长文再倒填虚构结构。按同一表达规则的关系检查做一次事实和语言核对，独立 review 同样读取该规则，发现的具体结构/语义错误可在最多两轮内局部修复并保留版本；仍失败标待处理。评分在冻结后只读进行，不能按分数循环扩写。

独立语义核对至少检查人物/道具归属、单一静态瞬间、空间与光线、跨镜连续性，并给对应镜头或文字证据。视频任务另按衔接六项检查本镜首尾及相邻切点，将具体镜号、参考图或正文证据和未解决冲突记入后台；可读性与动作可执行性由语义核对判断。JSON 格式通过只证明程序约束范围内有效，不能证明画面能执行；文本结论也不等于实际生成质量。
