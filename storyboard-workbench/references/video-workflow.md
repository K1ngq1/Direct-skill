# 视频镜头规划与验收

本模块把原分镜和已有图片整理成可执行的视频镜头文字、时间线及意见记录，正式交付仍按[三表脚本规范](visual-workflow.md#正式-excel-与后台日志)。不调用图片、视频、音频模型，不输出 MP4/HTML，不以规划文字或文件存在证明模型能力。原计划、静帧 Prompt、原图、人评及历史导出保持原件。

## 视频正文、参数与声音

新视频任务先向用户一次性问清画幅及横竖方向、试片分辨率、最终画质。已有明确答复直接沿用；未答复留待确认，不能替用户确认。选定后锁定，用户在生成前指出变化或明确确认变更时才调整，不因模型默认值静默改档。导演自行设计普通运镜与表演，不逐镜询问。

每镜交付自然正文与独立参数说明，两者不能混用：

- **镜头运动**：固定机位须写清景别与人物大小保持；缓慢拉近须写起止景别、方向与关注对象；升格感说明动作放缓的部位、轻重与节奏。不能同时要求景别不变和明显推近。焦距、光圈、焦点及清晰范围是导演设计，未获模型独立控制支持时放在正文，不能冒充硬参数。
- **人物、道具与环境变化**：逐人写初始姿态、视线、持物、动作及结束状态；用放松眉眼、呼吸、嘴角等可见表现表达情绪。手机放在哪里、哪只手仍握着、头发被风带起又落下、衣料和水面如何变化要可衔接。只写机位看得见的变化，不把每镜堆成多次事件。
- **时长**：后续规划优先整秒区间，如时间线 `0–3s、3–8s`，先按全片节奏划分，再核对目标模型的最短、最长、步进和当前模式。接口生成时长与剪辑采用时长分开；3秒剪辑不等于可向最短4秒的模型传3秒。需要较长素材时先规划可截取的动作与停顿，避免盲目延长全部镜头。超过上限在自然切点拆成多次任务并保持连续性，不偷偷截断；合并任务须确认当前模型支持多镜头且空间、人物关系可执行。旧版小数秒原稿与历史保留，新修订保留映射和理由。时间段、数值秒数、模型上下限不写进新 `videoPrompt`，由时间线和 MCP `params.duration` 控制；正文用开始、随后、稍停、结束等自然节奏表达。
- **声音**：先记录用户是否有指定 BGM、音效、对白或实际音频参考，没有则由导演按整片风格设计一条无歌词 BGM 或用户要求的音乐；音乐正文写配器、速度感、情绪变化、段落推进和对白避让，入出点留在时间线/参数说明。逐镜写同步音效与环境底声，连续镜头延续同一音乐，不各自生成一首。指定音乐须绑定真实音频来源；没有素材不能宣称已经接入。视频的声音开关不等于已经绑定该 BGM，也不保证可分离音轨。只请求文字时交音乐 Prompt，不生成音频。

参数说明包含用户已定的画幅、试片与最终清晰度、拟用模型、生成模式、声音开关，以及实际需要的生成时长/剪辑采用区间；未确定的项标待定。只保留实时 schema 支持的控制字段。没有 `fps`、`seed`、运镜强度或慢动作倍率控制时，不编造字段；“升格感”只是一项导演意图，不能声称生成了真实高帧率素材。

这些文本沿用下方可选字段进入 Excel，不新增自动调用器。模型选择、引用解析、能力检查和实际提交由宿主使用 LibTV 工具完成；校验文本字段不等于校验远端请求或动作效果。

润色沿用[四步表达核对](prompt-language.md#四步表达核对)，逐项对应已有的起始状态、变化部位、方向、必要接触或释放及结束状态。交接动作在接稳、松手等主语变化处明确执行者；只说明本镜实际需要的过程，缺失依据保留待处理，不补造动作。人物、摄影机与环境的运动分别交代，固定机位不强制增加运镜。静帧不扩写为连续事件，后期定格不改成运动生成。

合理性检查服从用户确定的风格：写实中发现支撑或接触冲突时指出具体关系；超现实、夸张与定格设计按其创作意图核对内部一致性，不自动改为跳跃、慢动作或现实动作。画质、时长和模型参数独立管理，“8K、电影级、动作流畅”等词不能代替可见的运动、光线与清晰范围，也不改变实际输出参数。

## 画面衔接与首尾帧设计

本维度用于视频的全片规划、Prompt 创作与独立语义核对，回答“上一画面留下什么、下一画面接住什么、变化如何抵达下一状态”。先确定相邻镜头的连接关系，再创作各镜正文；不增加静帧十一维字段或评分项。

### 先确定连接关系

- **同一视频镜头内的首尾变化**：首尾是同一段连续表演或运镜的两个状态，须交代中间可见动作和空间路径。只有首图时，尾状态按叙事目的设计并标明导演补全；无真实尾图不能宣称已核对首尾图片。仅因两图相邻，不能自动认定应合为一次连续生成。
- **相邻视频镜头间的剪辑**：明确延续动作、转移注意力、揭示因果、切换场景或表达时间变化。连接可以由动作、视线、构图、声音或情绪建立，也可采用明确硬切；换机位后的画面左右和像素位置不必相同，人物与场景的世界关系仍须成立。时空跳转按故事表达，不强求共同物体或连续穿越。

### 六项检查

| 检查项 | 创作与核对要求 |
|---|---|
| 衔接目的 | 说明为何从这一状态接到下一状态，以及连接发生在镜头内还是剪辑点；服务于本段必须读清的信息，静止反应和硬切均可成立。 |
| 承接对象 | 确定观众跟随的人物、道具、动作方向、视线、形状、声音或情绪；写清需要保持的身份和状态，以及允许变化的部分。明确跳转可无共同视觉对象，说明叙事依据。 |
| 首尾兼容性 | 对照实际绑定图片或已有文字核对姿态、持物手、接触和支撑点、人物朝向、空间轴线、门窗与光源。摄影机改变允许屏幕位置变化；只有可见路径能解释的变化才作为连续动作。参考图冲突写明具体位置，不能用“一致、无缝”代替处理。 |
| 中间变化路径 | 写清动作的起因、方向、必要接触或释放、经过的关键状态及抵达方式；动作数量与采用时长相称。连续动作切点核对动作阶段，避免无意重复或漏掉必要过程；风格明确允许的变形另行说明。 |
| 主体与摄影机分工 | 分别写谁在移动、摄影机如何运动、用什么环境参照读清运动；固定机位与人物靠近可以并存，固定人物大小与明显推近须消解冲突。越轴或大幅改变观察方向须有可读的空间交代，不通过镜像房间补齐。 |
| 结束与交接 | 确定结束动作阶段、注意力落点和下一镜如何接住；按需要安排稳定可剪点或在动作中切出，不要求每镜停住。声音可提前进入下一场或延续到切后，逐镜声音与全片音乐设计保持一致。 |

六项是检查依据，正文仍是一段自然、可执行的画面叙述；不要求逐项分段或每镜增加转场。真实参考缺失、遮挡无法判断或模型能力未经实测时，保留具体未知项。

### 按目的选择连接方法

术语用于导演判断，正式 Prompt 写清对象、方向、过程与落点；名称本身不代表模型支持的参数。可选方法如下，不逐镜套用：

| 方法 | 应写清的画面处理 |
|---|---|
| 保留对象承接（carry） | 同一可识别对象在前后状态中如何保留、移动或成为注意力中心；相邻剪辑可借它接续，镜头内连续运动须给出路径。 |
| 动作／视线承接 | 前镜在哪个动作阶段切出，后镜从哪个阶段接入；或前镜看向哪里，后镜揭示什么。确认方向、视线与动作因果，避免无意重演。 |
| 构图／形状匹配（graphic match） | 两个不同对象借位置、轮廓、运动方向或明暗关系相接；明确是剪辑匹配，不能默认物体在空间中变成另一物体。 |
| 遮挡／圆形扩展（iris） | 遮挡物如何进入并覆盖切换区域、从哪侧离开，以及揭示后的主体与空间；圆形扩展说明圆形来源和揭示落点，按片子风格采用。 |
| 推近穿越（zoom-through） | 摄影机推进哪个目标、目标如何占满画面、遮蔽或穿过什么、下一空间在哪里落下；核对真实路径，跨空间设计须符合已确定的风格。 |
| 快速摇移（whip pan） | 起始关注对象、摇移方向、模糊或遮挡如何掩盖切点、最终落在哪个对象及如何读清；无需摇移的镜头保持原拍法。 |
| 形变／汇聚（morph、gather） | 仅在创作意图允许时写清哪些元素改变形状或位置、按什么路径汇聚，以及最终识别对象；写实人物和场景的连续性不能靠默认形变补齐。 |
| 声音桥（J-cut／L-cut） | 下一场声音提前进入前镜，或前镜声音延续到下一镜；声音来源与入出点写入相应声音和时间线安排，不声称单段生成已完成跨镜混音。 |

例如，同一近景的表情首尾变化可写：“摄影机固定，人物头向、肩线和支撑手保持原位。开始眉心略紧，随一次自然呼吸舒展，嘴唇轻合，嘴角缓缓扬起，结束在克制的微笑。”若两图支撑手或朝向冲突，先记录参考不兼容。另如前镜人物抬眼望向门口，下一镜切到门边来人，可通过视线建立联系，两段各自交代可见动作即可。

### 写入与独立语义核对

评审同时读取共用表达规则，核对上述动作归属、运动分工与风格边界；对润色前后的状态、条件及接触顺序给出具体文本依据，不以“更流畅”概括通过。

沿用 `startState / action / camera / endState / invariants`：开始与结束状态写可见落点，动作写变化路径，摄影写观察方式，不变项保留身份、持物、方向等必要约束。相邻切点的交接写入相关镜头的开始／结束说明，必要时进入已有 `timeline[].description`；声音沿用 `dialogue/sound` 与全片 `musicPrompt`。维度不增加新的必填字段，也不另存第二份权威 Prompt；`videoPrompt` 的归属与复用按下方版本规则执行，静态 `prompt.text` 仍只写一个时刻。

独立语义核对按六项同时查看本镜首尾与相邻切点，在既有后台日志中记录镜号、连接关系、图片或文字证据、结论及待处理项；确实不适用须说明原因。真实图片冲突记入对应 `review.reason`，需要修改的图沿用 `needs-change`；缺图保留待处理。修订文本、重选参考或调整切法属于待处理建议，不自动修图、重生成或改写历史项目。现有 CLI 校验字段、哈希和引用，语义核对判断连接是否成立，实际生成效果仍须查看媒体。

方法吸收自 [onetake 的承接与运镜设计](https://github.com/feitangyuan/onetake/blob/013a61ac8d98883c73733f59c06e49e9ba444f14/references/motion-library.md)及[节奏与连接说明](https://github.com/feitangyuan/onetake/blob/013a61ac8d98883c73733f59c06e49e9ba444f14/references/rhythm.md)，结合本项目的视频工作流重新表述；其中动作／视线匹配与声音桥为本项目的剪辑方法补充。本规则自包含，无需安装上游 Skill 或执行其代码；上游针对 DOM／Canvas 的位移阈值与衔接评分不作为生成视频的质量标准。

## 省额度的执行流程

以下仅在用户明确进入媒体生成阶段时执行；选好参数、创建文案或填写表格均不等于授权本轮媒体生成。

1. 复用已有确认、计划、素材和本轮仍适用的模型查询结果，仅查当前阶段需要的节点与 schema，不重复读取整张画布和全部模型。先挑少量最关键的镜头试片，默认每项一份，不自动加候选、重试或启动多轮 Agent。
2. 在用户选择与模型支持范围内，先用480p或720p低清试片。判断人物、站位、动作、表情、持物、运镜和声音是否正确，再决定是否升级。分辨率更高不能修正错误动作或人物关系。
3. 满意的低清视频沿用其真实原任务和原件走平台专用样片升级。保留源节点、所选输出、任务与升级回执，回读升级结果再用于后续节点。不能通过再次文生视频、图生视频或普通 `video2video` 冒充画质升级；普通参考生成可能重做动作并再次计费。没有升级资格或工具不支持时说明具体原因，暂停升级，不能换模型或偷偷重新生成。
4. 遇到复杂多人站位、交叉遮挡、长链条动作或一次针对性修正仍难以确定方向时，先问用户是否用导演台和火柴人站位图确定机位、人物位置、视线与运动路线。用户选择后只做必要的一张或最少关键帧，确认方向再回到低清试片；简单镜头不增加这个阶段。导演台可能也消耗额度，不自动启动。不存在专用火柴人工具时采用用户同意且实际可用的图像工具，不编造端点。
5. 未知提交先恢复原任务；已失败只针对原因处理，不能换幂等键盲目重发。执行次数、预算和范围沿用用户授权，查询/文字确认不升级成无限试错授权。

## LibTV MCP 参数与画布接入

以当前工具 schema 与实时模型返回为准。会话开始用 `doctor` 核对连接；操作画布前用 `target_project` 锁定真实项目 UUID，不能用项目名称猜测，也不能传数字数据库 ID。读取目标节点及版本后再改动。

| 需求 | 实际入口与字段 |
|---|---|
| 发现视频或音乐模型 | `search_models(action:"search", nodeType:"video"/"audio")`，按需求筛选后 `get_model(model:<返回的完整名称>)`；核对 `schema` 与 `remoteExecution.controlsByMode` |
| 只检查视频请求 | `validate_generation_plan`，输入完整模型名称、模式、Prompt、`params` 和真实引用节点；预检不证明生成质量 |
| 新视频节点与位置 | `generate_video` 的 `projectId/name/group/x/y`；`run:false` 仍会创建节点并预检，不能当纯只读；`run:true` 才执行生成 |
| 媒体参考 | `generate_video.referenceImageNodes/referenceVideoNodes/referenceAudioNodes` 使用本项目真实节点，首尾图顺序准确；不把本地图片 ID 当远端节点 ID |
| 普通节点与连线 | `create_node` 的 `left/right`；修改先 `read_node`，再 `update_node` 的 `leftAdd/leftRemove/leftEnsure` 或对应 `right*`；不手写 `params.imageList/videoList/audioList` 及排序字段，也不通过更新改变节点类型 |
| 视频参数 | `generate_video.params` 仅传该模式真实支持的字段；`model/mode/prompt` 位于工具外层，由工具管理的媒体列表和身份字段不能塞入 `params` |
| 样片升级 | 原成功样片的 `get_draft_video` → `promote_draft_video(run:false)` 核对资格与当前账户报价 → 已授权时同一原件 `run:true` → 按升级回执返回的 `task_id` 回读；多输出用实际 `outputIndex`，不能用已完成的低清任务代替升级结果 |
| 音乐节点 | 单独查询音乐模型，用 `create_node(nodeType:"audio", run:false)` 配置真实模型参数和音乐正文；只有授权后才执行。对已完成 BGM，后期统一对齐、混音；需要当视频模型输入时再核对音频参考模式 |

画布“上一视频到下一处理节点”的关系必须对应真实升级结果。专用升级服务自行沿用原任务，调用方不替换源媒体、模型或 provider 任务身份；当前 `promote_draft_video` 不提供自由指定目标节点、位置或连线的参数。先回读它返回的目标节点与媒体，再按实际可用接口组织画布，不能先创建一个普通生成节点假装是升级节点。

已核对的接口示例（2026-10-20，生成前仍需确认没有漂移）：`Seedance 2.5（样片模式）` 支持480p，常规生成 `duration` 为4–30秒、步进1，比例含16:9，声音参数为 `enableSound:"on"/"off"`。这一模式没有720p选项。样片升级路由核对七日资格并面向1080P，是否适用于本片必须等真实成功样片出现后检查，不能由模型名称推定。

```js
// 示例；projectUuid、imageNodeId、完整正文和版本均从当前项目读取。
const request = {
  projectId: projectUuid,
  model: "Seedance 2.5（样片模式）",
  mode: "singleImage2video",
  name: "镜头样片",
  prompt: videoPrompt, // 画面、动作、运镜、声音；不含时段或模型能力说明
  params: { ratio: "16:9", resolution: "480p", duration: 5, enableSound: "on" },
  referenceImageNodes: [imageNodeId]
};
// validate_generation_plan(request) 只预检。
// generate_video({...request, idempotencyKey: stableKey, run: false, x: 640, y: 0})
// 只创建/预检；实际执行须有本次生成授权，不能仅因示例中出现调用就提交。
```

本例不传虚构的 `fps/seed/camera`。`enableSound:"on"` 允许按正文生成声音；统一配乐时正文明确只生成需要的环境声、同步音效/对白，BGM独立制作并后期混合，不能承诺模型一定输出干净分轨。若整个视频调用关闭声音，则把所需音效和对白留给后期。

音乐参数单位也必须按 schema 核验。例如当次 `ElevenMusic V3` 的 `duration:30000` 是30秒，远端映射为 `music_length_ms`，与视频的秒数不同；最低30秒不意味着必须将剪辑配乐延长至30秒。数字与接口字段放参数说明，不混入音乐创作正文。

同一 `generate_video` 调用仍在等待时不另发生成或并发轮询；调用结束并返回待恢复任务后，才用原身份查询。其他异步工具按实际回执恢复。接收、预检、报价、连线、模型自述和画布可见都不代替最终媒体验收。

## 版本状态与正文

独立状态使用 `schemaVersion: 1`，保存在 `video-workflow/revision-000001.json` 等不可覆盖的新版本，兼容 `visual-excel-v1` 与 `visual-excel-v2`。`projectId` 绑定项目，正整数 `revision` 区分修订，`sourcePlanHash` 绑定原计划实际内容；计划或图片变化需重新检查，不能无声刷新旧结论。

| 字段 | 内容 |
|---|---|
| `images` | `{id,shotId,locationId,characterIds,path,sha256,review,selection,approval,productionNote?}`，绑定真实可读文件、源镜号、场景与人物；可选 `productionNote` 只写面向制作的短提醒，详细评价留在 `review.reason` |
| `assetImages`（可选） | `{assetId,path,sha256,description?}`，绑定人物或场景参考图；可选 `description` 为读者直接使用的精简设定，不覆盖原稿 |
| `shotPrompts`（可选） | `{shotId,text,basis,references:[{assetId,path,sha256}]}`，本轮静帧正文与真实参考修订；按稳定镜号覆盖展示与提交正文，冻结原计划保留作来源，不沿用旧正文评分 |
| `generationSource`（可选） | `{path,sha256}`，明确绑定本次实际生成批次的 `items[{id,status,output:{path,sha256}}]` 记录；检查成功输出后使用，不由旧批次的计划状态推断当前结果 |
| `videoShots` | `{id,shotIds,startImageId,endImageId,startState,action,camera,endState,invariants,durationSeconds,dialogue,sound,videoPrompt?}` |
| `timeline` | `{shotId,seconds,reason,description?}`，按原分镜顺序记录预演秒数及调整原因，用于累计时间；可选 `description` 为逐镜自然摘要，配对帧各自描述本段状态与动作，不能在1秒起点行重复整段2.5秒表演 |
| `pilotVideoShotIds` | 本次重点试用的视频镜头 ID；不据此省略全片规划 |
| `results` | 实际生成及验收记录；未执行生成时为空，导出显示“未生成” |
| `generationSettings`（可选） | 全片视频参数的非空说明文本，记录用户选择与导演制作选择；不是可执行配置，不保存虚构远端任务身份 |
| `videoShots[].generationParameters`（可选） | 本镜独立参数说明文本；时长与模式进入此处及真实工具调用，不拼入自然正文 |
| `musicPrompt`（可选） | 全片音乐的独立自然正文；模型参数、数值时长与剪辑入出点放参数说明 |

- `review` 使用 `{status,reason,reviewer}`，状态为 `usable/needs-change/pending`，显示“可用／需修改／待确认”。检查原因具体到人物、视线、手臂、道具或画面，不用高分代替问题描述。
- `selection` 使用 `{by,reason}`，`by` 为 `agent/user`；`approval` 使用 `{status,by}`，状态为 `pending/confirmed`。只有用户真实确认才能记录 `confirmed` 且 `by:"user"`；选定方案、Agent 检查和用户确认互不替代。
- 正式起始参考需要 `usable` 且用户已确认。问题图或未确认图可作预演占位，脚本备注说明具体缺口；生成失败的镜头不伪造图片记录，失败原因留在后台日志。无起始或结束图使用 `null`，复用则引用真实同一图。
- 每个视频镜头说明开始的可见状态、逐人动作和速度、运镜、结束状态、前后衔接，以及需要保持的人物、场景、持物和方向。`invariants` 为文本数组；对白沿用原稿，新增临时声音或制作文字标为导演补全。
- 静帧配对可由多个 `shotIds` 组成同一视频镜头；时间线仍覆盖原分镜，起止帧不重复计时。原计划秒数保留，预演调整写明原因，不以覆盖原秒数解决冲突。
- 原镜已有 `videoPrompt` 时，单镜规划省略该字段并引用源正文；显式提供时必须相同。原镜没有视频正文或多个静帧合为一个视频镜头时，才在该视频镜头保存新增 `videoPrompt`。静态 `prompt.text` 仍只写一个时刻，不拼入动作过程；结构字段用于检查，不由程序拼成第二份正文。
- 实际结果未生成时，动作自然度、模型可控性和成功率保持“未验证／未知”；既有静态文本评分与独立 `textscore` 不用于评价这些项目，不自动重评分。

## 命令与导出

```text
node "<skill>/scripts/video.mjs" finalize "<project>" "<input.json>"
node "<skill>/scripts/video.mjs" seal "<project>" "<input.json>"
node "<skill>/scripts/video.mjs" validate "<project>" "<revision.json>"
node "<skill>/scripts/video.mjs" bind-excel "<project>" "<revision.json>" "<existing.xlsx>"
node "<skill>/scripts/video.mjs" export "<project>" "<revision.json>"
node "<skill>/scripts/video.mjs" feedback "<project>" "<revision.json>" "<feedback.json|xlsx>"
```

`seal` 读取已归档项目与冻结原计划，校验引用并绑定当前文件哈希，生成新版本；不改原计划或输入文件。`validate` 核对项目身份、原计划、图片、镜头引用、时间线和确认状态。已有正式 Excel 先用 `bind-excel` 绑定对应规划版本，保留原路径，不搬动或另做副本；新项目首次普通 `export` 后自动固定该文件。后续 `export` 按[共享导出规范](visual-workflow.md#正式-excel-与后台日志)在同一文件替换文案值，无变化不重写，排版、图片、链接和用户意见保持不变。原稿、封存 JSON、内部备份及真实人评继续保留历史。

正常批次交付优先单次 `finalize`，在各张结果独立保存后统一封存并导出，不依次重复执行全部命令。它保留封存和导出的必要边界校验；成功返回 `stateSaved:true/exportsUpdated:true`。若封存成功而 Excel 更新失败，返回 `stateSaved:true/exportsUpdated:false`、封存路径及具体冲突，CLI 退出码非零；只修复实际问题，不重新提交媒体。已封存且内容未变时用原版本 `export` 恢复交付，只有输入内容确实变化才另行封存。`seal/validate/export` 继续供分阶段操作、诊断与恢复使用；媒体并发与单项失败处理按[共用批次流程](media-execution.md)。

Excel 不另建图片验收、视频规划、时间线或结果验收工作表。画面与动作、对白与声音、摄影与运镜、衔接及预计起止时间进入“分镜脚本”；完整视频正文进入“生成Prompt”；参考图进入相应主表与资产表。图片选择、检查证据、版本、来源映射、失败和反馈绑定详情只进入后台 `制作日志.md` 与 JSON。

首次制作包含参数/音乐字段时，“生成Prompt”沿用三列安排“全片视频参数”“视频参数”“音乐”行；参数不能当视频正文链接目标。已绑定的正式文件只更新已有对应位置，新增类型、改变镜头关系或文案超出现有续行空间时保留原文件并指出位置，不自动插行或重做排版。旧版本缺省这些字段时不补造。正文与参数分别完整保留，长文本按完整段落使用既有续行空间。

## 用户意见导回

正式 Excel 的“分镜脚本”第10列“用户意见”为意见导回区。绑定及每次更新保存实际交付工作簿的内部基线，导回时按对应版本的真实基线校验正文、镜号、图片和绑定，不能重新生成默认排版作比较。用户调整字体、列宽或行高不应造成正文版本误判；正文、图片或绑定不匹配时保留用户文件并报告，同一内容重复导入不重复记账。填写意见只记录意见，不自动改稿、确认图片或创建评分。

用户在 Excel 直接修改的正文不自动回写规划 JSON；后续新源同时改到同一单元格且产生冲突时，保留原件并指出位置，不能覆盖用户文字。意见列始终保留，不因换版清空；换版时标记继承意见，文字未变则不登记为新版反馈，用户新改写后可正常导入。首次绑定已有但尚未导入的意见仍可导入。后台保留各次实际交付基线与版本，避免把旧意见错绑为新稿反馈。

JSON 反馈为 `{schemaVersion:1,projectId,revision,workflowHash,comments:[{shotId,note}]}`。`workflowHash` 绑定对应完整工作流版本，由工具或调用方依据实际版本计算，不手填假哈希；`note` 接收文本和数字 `0`，空白不算意见。未知或重复镜号、错误版本及被篡改的绑定需明确报错。记录保存在 `video-workflow/feedback/<内容哈希>.json`，同时生成同名 Markdown 后台日志，保留实际意见及版本、正文和图片绑定。

旧 `visual.mjs feedback <project> <ratings.xlsx>` 继续读取历史人工评分合同，0分仍是有效填写；与本模块的制作意见分别保存。用户没有填写的项目保持空白，不代填或从 Agent 检查推断意见。原稿、历史评分、图片与已确认素材不是临时产物，不在收尾删除。
