# 固定分镜框架：按叙事目的推荐拍摄方案

普通TXT/Markdown故事采用[完整默认草案流程](story-planning.md)：先全片事件和状态、再每镜一套拍法，recommendation不冒充用户选择/确认。新故事默认总表并可导出草案，原XLSX/人工模式保留逐镜选择。下面的框架与人物引用方法共用；有关答题与全片选择的描述仅用于原人工模式。

用户使用固定十列表格、单格或框选批注。八个制作方面仍作源字段，各字段只写独立信息，不为填满表格重复表述。程序读写数据、展示和准备清单，Agent执行导演判断；网页不调用模型。

## 项目层

先在对话中询问缺少的用途、交付物、分辨率、画幅、时长和风格，最多三问一轮，允许“请推荐”。已知答案直接使用，不要求用户填专业设备或光源表单。目标保存为brief及画幅/时长；productionConstraints只作内部依据。设备仅在用户提供时写入，未提供则省略。未知真实布局保留待核对，不编造现场参数。

提取角色清单与场景分组，分别记录依据与提案。同一角色的不同称呼依据原文确认后归为稳定身份；参考图文字不等于角色年龄已确定，不同活动是否在同一空间需核对。定格和反打不天然增加场景，画外音不天然增加有外观的演员。

## 每镜源字段

| 框架字段 | 内容 |
|---|---|
| 镜头内容 | 定格瞬间正在发生的单一动作及当前状态；本轮不创作motionPrompt |
| 景别、拍摄方式 | 景别shotSize、机位position、焦距focalLength、景深focus；equipment仅用户提供时写入 |
| 光影、色调 | 决定画面的光向、软硬、明暗、冷暖，与相邻镜保持连续 |
| 角色描述 | 有shotSchema时由结构只读投影，逐人包含名称／资产ID、实际参考、必要可见特征及状态，并附道具关系；旧无schema时原方式编辑 |
| 场景描述 | 地点、必要的时间或环境条件、必要布景；未见参考的户型标提案，不擅自镜像 |
| 构图与空间层次 | 主体落点、前中后景、轮廓遮挡、留白、视线与信息读取顺序 |
| 姿态与表情 | 有shotSchema时只读投影人物姿态，修改进入“编辑人物与道具”；旧无schema时只补人物栏未覆盖重点，可空 |
| 材质与画面质感 | 必要的可见纹理或反光，可留空，不堆空泛质感词 |
| 连续性与限制（详情区） | breakdown.continuity：必须沿用的设定、本镜变化和少量关键错误限制；不增加主表列 |

用variant.shotSchema保存人物、道具与关系；其他源字段保存于variant.breakdown。先填schema的subjects/props/relations及实际参考，再用Humanizer润色中文描述一次，程序派生人物、姿态格与最终Prompt，不先写长文再拆结构。有schema时characterAssetIds、referenceIds及breakdown.characters/pose均为投影，不双份维护。旧无schema方案保留原编辑方式。字段和校验见[单镜人物、道具与关系](data-contract.md#单镜人物道具与关系)。推荐理由可留在shot.recommendation，不拼入静帧，不代替用户采用或确认。

新导入项目采用staticPromptFormat="concise-v1"。有框架时，composeStaticPrompt按以下六类汇总源字段：**画面瞬间**content → **场景环境**scene → **镜头与构图**camera精简项＋composition → **光影与风格**lighting＋texture＋brief.style → **人物与关系**shotSchema（旧无schema时characters＋可选pose） → **连续性与限制**continuity。风格只说明一次，空项省略，不填占位句。画幅、分辨率单列为规格，不反复写进正文。主正文以约200–300字为目标，通过删重复精简，不硬截断、不为凑字数加内容。

Agent只创作或修改源字段；网页、复制、Markdown、Excel和提交清单使用同一派生正文，不另写简版。静帧展示与正文不含ISO、快门、帧率、F值、测光说明、选择理由和备用参数。历史13项camera数据保留兼容；缺少staticPromptFormat的旧项目维持原汇总格式，不自动迁移。无框架旧方案、补帧、场景与三视图继续独立编辑；空景和三视图只写各自必要内容，不强套叙事六类。

## 一稿与一次核对

1. 读目标、工作稿、角色资产和实际参考，确定观众必须读到的单一瞬间、人物关系与空间。
2. 先填写单镜人物、道具与关系结构，再完成其余源字段的一稿，安排主体位置、景别机位、焦距与清晰范围和必要光影。多人笑点必须让相关人和物可读；不能只凭F值保证同时清晰。
3. 读取[中文 Prompt 润色适配](prompt-language.md)与随包[Humanizer-zh](humanizer-zh/SKILL.md)，做一次信息与语言核对：保留身份、方向、道具、确定程度，删重复、翻译腔和空话。不进行多轮自评、扩写或评分。
4. 快切各子段另存补帧，定格复用已有画面；历史动作Prompt保留原值。设备或曝光解释留在必要的内部制作记录，不进入精简静帧正文。

## 静态交付完整性

- 逐镜检查全部已创作拍法的staticPrompt，不仅检查角色三视图。每条描述一个确定时刻，只写本镜需要的可见角色特征，不复制整套人设。
- 快切各子段、表情首尾等顺序静帧分别写为shotFrames，绑定原镜号及拍法；它们补足同一拍法，不是互斥替代，不增加原镜时长。主静帧仍保存于variant.staticPrompt。
- 每个场景资产应有独立空景/多视角Prompt；多视角共用可核对的空间关系，空景不添加人物。未知真实户型、服务区是否同房等须标提案，不能让三张视图变成三个不同场景。
- 沿用前镜的定格保留复用指令，不能为凑全镜号另创一张不连续画面。
- 网页默认逐镜答题，候选全文展开，选择保存后前进，顶部镜号可回看和重选；不在答题页堆评分、推荐或设计说明。原理由和完整框架保留。“全部 Prompt”“场景静态 Prompt”可集中查阅，完整静态导出包含未采用方案；用户采用状态与文本覆盖率分别报告。

## 角色设定与分镜引用

这是整个 Skill 所有项目默认必须遵守的创作规则，适用于新建、修订、批注、导出和后续提交，不只约束某个样例。

先建立或复用 `productionInventory.characters` 中的角色资产：每个角色具有稳定 `id`、项目内唯一 `name`、实际入镜的 `shotIds`，依据和待定项分别记录。复用已有身份，不因换拍法新建同一角色。若不同角色同名或脚本有别名，先消解人物与资产的映射并确定可区分的名称，再创作分镜；不靠同名字符串猜关联。缺资产时先从剧本和已核验参考登记已知事实，外观不足写待定，不为填满资产而捏造人物长相。

角色外观先问关键缺口，未回答不猜；回答“请推荐”才细写相应年龄、面孔、肤色、皮肤状态、发型、体型和服装，标为提案。完整设定保留在角色资产，并用于角色三视图；分镜可引用其中本镜必要的可见特征和服装，不能把提案变成已采用事实。人物三视图共享稳定 ID 和身份，不因角度切换改五官；不能因分镜文本缩短而删除资产设定。

内部名称由schema的assetId定位，参考使用实际附件ID；模型正文按[人物指代规则](visual-workflow.md#人物指代内部身份与模型正文)使用实际角色图引用或可区分的必要可见描述，不能把登记过的专名当成身份说明。“儿子／妈妈／爸爸”等剧情称呼可保留，但无图时仍需必要特征；不设通用称呼。旧表格显示内部name不代表模型已经认识该人，也不自动迁移历史项目。subjects逐人独立记录必要可见外貌、服装、位置、朝向、姿态、手部、视线、表情和可见部位；props记录道具当前状态、位置与holderAssetIds；relations记录gaze/contact/occlusion/sameFrame及其人物/道具ID，明确谁看谁、谁接触谁、距离遮挡与必须同框者。只用现有资产、原稿或实际参考，不臆造外貌或参考绑定，不从中文剧本推定族裔，不复制整套人设。旧无schema方案仍可编辑characters和可选pose，不自动迁移。

使用稳定关系记录关联：角色资产shotIds指向关联镜头，promptSections.assetIds指向独立Prompt关联资产，参考记录可选assetIds显式关联图片中的角色/场景。有schema时variant.characterAssetIds由subjects投影，variant.referenceIds由schema通用、人物和道具参考合并投影；不再另行维护。旧无schema时由Agent核对真实入镜ID，无人物显式记空数组；缺字段的旧方案只作待核对候选，不按关键词或shot.characters全名单猜关联。资产ID和参考附件ID不混用，登记关联不创建图片或代替视觉核验。资产更名按稳定ID审核，导入original、来源和历史保持原样，不机械全局替换。

角色名称只是文本引用，不代表模型已经识别人设。LibTV 清单须将名称、稳定资产 ID 与实际三视图图片参考分开关联，不额外拼入资产外观全文。只有三视图 Prompt 而没有图片时，明确记录“参考待生成”；不能宣称身份参考已就绪或人物一致性已验证。当前只准备本地清单，不执行LibTV生成。

## 修改与同步

角色外观变动后更新关联三视图，并核对分镜名称、本镜可见特征与状态；若本镜无须变化，保留原值，不为解除同步标记而强行改字。名称变化仍按稳定 ID 检查关联，不能仅靠文本替换。场景以稳定ID记录布局、陈设、材质和环境；关联到镜头及空间三视图。

单格和框选批注都绑定稳定目标与字段，读取提交时原文、版本和当前内容。框选按groupId理解共同要求、逐格回应与展示差异，未处理的成员继续待处理。用户直接改工作稿后，以该工作稿为创作输入；不能拿导入原稿覆盖用户编辑。对同镜不同拍法的批注不可串用。专业参数改动要说明可见效果变化，静态主题修改也要同步静帧Prompt。

修改源字段立即重组静态Prompt，不另设待改写文案。有schema时人物与姿态格只读，“编辑人物与道具”打开结构化表单；schema沿用稳定shotId/variantId的字段编辑与批注，禁止用数组索引持久化目标。已有工作稿、目标或共享资产变更的promptNeedsSync仍需语义核对，普通编辑不得清除。static模式完整核对后提交breakdown及需变更的shotSchema；static-motion还需motionPrompt。兼容提交staticPrompt必须与派生值完全相同。旧模式兼容，历史视频保留；状态解除不是生成图像效果通过。

网页完整框架请求使用category=production。回应该请求须完整核对并提交breakdown；static-motion还需动作Prompt，不能只改参数字段就标已处理。保留原稿、用户选择、历史及未涉及镜头，展示前后参数/可见效果差异。

全片每镜已选择并确认最新方案，且没有阻塞批注或待同步项后，才准备前三镜静态图清单。只收录每镜采用方案，冻结实际Prompt和参考；清单prepared不等于生成授权或效果通过。相关批准内容改变后按stale处理并重新核对，不拿旧快照冒充最新方案。
