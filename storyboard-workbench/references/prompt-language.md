# 中文 Prompt 润色适配

中文 Prompt 创作与修订使用随包的[Humanizer-zh](humanizer-zh/SKILL.md)。先明确画面事实、人物道具关系与镜头目的，再组织自然正文，按下方[四步表达核对](#四步表达核对)完成一次事实与语言核对。目标是减少空话、保留事实、直接表达真实关系；通顺文字保留，不靠多轮扩写或评分改进措辞。

本页维护各平台共用的表达规则。新 Excel 模式不使用旧六类拼接器；旧项目的字段编辑、F值隐藏和派生正文要求已集中在[旧工作台入口](legacy-workbench.md)，仅继续旧模式时读取。

## 新 Excel 模式怎样用

1. 读本次目标、工作稿、结构、资产和实际参考，先确定单帧视觉重点。保留人物、道具、位置、方向、表情、光源与确定程度；原文事实、用户确认、导演补全及未知项分开。润色不补剧情或偷偷解决关键冲突。
2. 按画面组织自然正文：主体的动作、视线、手部与持物尽量集中；多人逐人说明，再补共同空间、构图、摄影和光色。维度不要求固定顺序或六段标题，完整人设不隐藏拼入请求。最终正文与来源/结构版本绑定，不从导出的 Excel 反写另一套权威文本。
3. 按下方四步顺序核对正文，保留取景范围、方向、道具归属、否定、条件及不确定性。新版保留焦距、光圈、焦点与清晰范围，注明导演建议及基准；未提供时不编造相机品牌型号、ISO、快门或实拍数据。约200–300字只是普通主帧参考，不截断必要信息或凑字数。
4. 具体硬校验/语义错误按[工作流](visual-workflow.md)最多两轮局部修复；保留原始版本和差异，仍失败待处理。只读评分和重写建议在冻结后单独记录，低分不触发修复循环。修订保留 ID、参考、原文、用户编辑和历史，不自动采用候选或确认质量，不改未授权的历史视频字段。

## 四步表达核对

适用于本次授权的新稿或定向修订中的人物、场景与分镜 Prompt。先以原稿、用户要求、已确认设定和本次结构为保留基线；原有十一维、静帧时刻、摄影约束、参考绑定、连续性及交付规则继续生效。仅调整表达，不借润色改变画面设计或确定程度。

四步是一次核对中的顺序，不是四轮生成，也不增加逐步确认。诊断与必要差异使用已有检查或修订记录，和最终正文分开，不新增 Excel 工作表或四套交付稿。用户明确只要求诊断时，到第一步结束。

1. **先诊断，不改写。** 先定位有问题的原句或短语，记录对应镜头／资产、原文位置、问题及必须保留的信息。只标真实问题，例如空泛评价、同义重复、抽象动词、主语含混、长句中关系堆叠、模板式开头或总结；此步不输出替换句，不边诊断边重写。没有问题的文字原样保留。
2. **删水分。** 对已定位的套话、空话、重复铺垫和重复总结，确认删除后没有丢失独立信息再删。用于识别不同人物或保证单条 Prompt 独立可用的重复描述，不能当成全片冗余批量删除。用户指定的风格、神情强度、数量、范围、比较、条件、否定、来源性质和必要摄影术语都属于信息，不能因“像模板”删掉。
3. **改骨架。** 用已知的具体动作替换抽象动词，例如“右手对白瓷杯进行握持”改为“右手握着白瓷杯”。原稿及结构没有具体动作时，保留其概括程度或记录缺口，不能把“表达关心”自行写成“伸手拍肩”。按主体、动作和实际空间关系拆开堆叠长句，保持谁做什么、谁看谁、谁拿什么及条件的对应；不凭空添加因果或先后关系，不把同一静帧拆成连续事件。优先直接、主动的句子，必要的术语与准确关系照常保留。
4. **反向查残。** 从编辑角度通读一次，检查是否还剩换个主体也成立的套句、无信息的收尾、含混指代、刻意转折、重复评价，以及专业画面描述中通常不会这样写的句子。同时逐项对照保留基线，查新增、遗漏、关系错接和确定程度变化。只处理能指出具体问题的局部；“像 AI”不是独立改写理由，不为追求人味加入经历、感想或新事实。核对结束即进入既有硬校验、独立语义核对与冻结流程；具体错误仍服从最多两轮修复的限制，评分不触发再润色。

四步中的具体判断如下；沿用一次核对与最多两轮局部修复的边界：

- **诊断**：明确原句必须保留的主体、动作、数量、方向、否定、条件和确定程度。区分语言歧义、设计信息不足与事实冲突：歧义有已知依据才消解；缺口保留未知；冲突指出不能同时成立的具体要求，不通过润色替用户选定方案。
- **删水分**：按镜头目的保留影响识别、动作执行与连续性的内容，再合并重复辅助细节；不因背景次要就删除独立事实，不补空泛画质词凑长度。
- **改骨架**：动作靠近其主体，方向、程度与条件靠近作用对象；同一人物的姿态、持物与视线集中表达，交接或主语切换处明确执行者。按视觉重点组织自然段，让辅助环境承接主体所在空间，不逐项串接维度。
- **反向查残**：逐项核对原句与新句的含义，尤其是“仅、仍、才、若、约、轻微”等限制与程度，并用下表检查要求能否同时成立。通顺不等于等义，维度齐全不等于画面可执行。

| 关系 | 核对问题 |
|---|---|
| 主体与动作 | 移动、注视、持物、支撑和接触分别属于谁？代词或修饰语能否被误接到另一人或物件？ |
| 空间与方向 | 人物自身左右、当前画面左右与场景固定方位是否分清？换机位只改变投影关系，不搬门窗或交换持物手；依据不足不猜坐标。 |
| 动作与可见范围 | 关键手部、接触点与道具是否处于取景内，是否被身体或前景挡住？完整入画与裁切要求是否冲突？ |
| 摄影与清晰范围 | 景别、观察方向、焦点和必要清晰范围是否协调？不能用一个焦距或光圈数值保证不同距离对象都清楚。 |
| 光线与材质 | 必须读清的表情、接触与纹理是否有相容的光向和明暗条件？质感词不能替代具体可见依据。 |

只查本镜适用关系，不新增固定字段、正文段落或评分项。若解决问题需要改动作、布局或拍法，将方案作为导演补全另列；用户锁定的冲突保留待处理。

## 适合 Prompt 的表达

- 按“谁／什么，在什么位置，呈现什么动作或状态”组织句子，尽量用直接动词。长定语妨碍理解时拆开，不能拆散物件与人物的对应关系。
- 先交代本镜视觉重点，再让后句承接前句。默认用清楚、简短的自然段，每段围绕一个画面重点；只有信息确实并列、有顺序或需要比较时才用列表，不把正文排成字段清单或多层提纲。Excel 表格结构与内部检查项照常保留。
- 把已有的可见细节说清楚；只有“高级、电影感、富有感染力”而没有依据时，不凭空补上灯位、表情或材质。需要新增设计时作为导演提案另行说明。
- 内部保留角色名称与稳定 ID；模型正文按[人物指代规则](visual-workflow.md#人物指代内部身份与模型正文)使用真实图片引用或必要可见特征，不把专名当成模型认识的身份。可以保留“妈妈／儿子”等有意义的角色称呼，避免“她／对方／该人物”的歧义。完整人设留在资产与三视图，不整套复制；实际没有身份图时不能写“沿用参考图”冒充就绪。
- 不把制作 Prompt 改成随笔、口号或聊天：不添加作者感想、第一人称经历、情绪化旁白。静帧保持一个确定时刻，不用“接着／随后／逐渐”扩成连续动作。
- 参数和技术术语可自然保留英文。画幅、分辨率与接口配置内部管理，摄影要求自然写入新版正文；不把 JSON 字段名、机器 ID 或配置对象当作画面语言，不增加自动词语替换或“人味分”。
- “值得注意的是”“总而言之”、设问自答、“不是X而是Y”、空泛程度词和生造术语仅作为检查线索；没有提供新信息时删除，有真实强调、比较或限制作用时保留含义。用普通词和准确动词说明关系，不把截图中的英语例词做成全局禁词表。写法截图只指导表达，不提供剧情、人物或场景事实。

下面是独立教学例句，不来自用户项目；“小林”是内部角色名称。它们只展示局部语言处理，不能当作经用户确认的优质基线；最终正文仍须用实际图片引用或必要可见人物描述，不能仅凭已登记名字直接提交。

| 字段 | 改写前 | 改写后 |
|---|---|---|
| 镜头内容 | 小林站立于柜台右侧的位置，右手对一只白瓷杯进行握持，视线被投向画面左侧的门口。 | 小林站在柜台右侧，右手握着一只白瓷杯，看向画面左侧的门口。 |
| 姿态与表情 | 小林的双肩呈现出放松的状态，下巴保持微抬的状态，嘴角带有轻微上扬的弧度。 | 小林双肩放松，下巴微抬，嘴角略微上扬。 |
| 光影／色调 | 在窗户位于画面左侧的情况下，建议使用柔和的窗光对小林左脸进行照明，窗户实际位置仍有待确认。 | 若窗户在画面左侧，建议用柔和窗光照亮小林左脸；窗户实际位置待确认。 |

第一例保留柜台右侧、右手、白瓷杯、视线及画面左侧门口；第二例保留同一时刻的三个姿态信息；第三例仍是有条件的布光建议。不能仅以字数减少或模型自评分判断改写成功。

另两例只展示何时不能直接改写，不是项目事实或固定镜头模板：

- **信息不足**：“两人站在门边，他把伞递给她。”若身份与持物依据缺失，指出递出者、接收者尚不明确；不擅自补性别、左右手或谁站门内。
- **要求冲突**：“只取眼睛至下巴的面部特写，同时完整拍到腰间双手。”保留两项要求并指出取景冲突；扩大景别属于拍法变更，不能作为等义润色静默执行。
