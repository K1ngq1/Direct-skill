# 中文 Prompt 润色适配

中文 Prompt 创作与修订使用随包的[Humanizer-zh](humanizer-zh/SKILL.md)。先明确画面事实、人物道具关系与镜头目的，再组织自然正文，按下方[四步表达核对](#四步表达核对)完成一次事实与语言核对。目标是减少空话、保留事实、直接表达真实关系；通顺文字保留，不靠多轮扩写或评分改进措辞。

本页维护各平台共用的表达规则。新 Excel 模式不使用旧六类拼接器；旧项目的字段编辑、F值隐藏和派生正文要求已集中在[旧工作台入口](legacy-workbench.md)，仅继续旧模式时读取。

## 新 Excel 模式怎样用

读取本次目标、工作稿、结构、资产和实际参考，先确定单帧视觉重点。按下方四步核对，在随后的章节处理摄影与引用；正文不设字数上限。版本、局部修复和交付保护按[执行约束](../../AGENTS.md)，具体命令按[交付合同](visual-workflow.md)。润色不补剧情、不擅改历史字段，也不从 Excel 反写另一套权威文本。

## 四步表达核对

适用于本次授权的新稿或定向修订中的人物、场景与分镜 Prompt。先以原稿、用户要求、已确认设定和本次结构为保留基线；原有十一维、静帧时刻、摄影约束、参考绑定、连续性及交付规则继续生效。仅调整表达，不借润色改变画面设计或确定程度。

四步是一次核对中的顺序，不是四轮生成，也不增加逐步确认。诊断与必要差异使用已有检查或修订记录，和最终正文分开，不新增 Excel 工作表或四套交付稿。用户明确只要求诊断时，到第一步结束。

1. **先诊断，不改写。** 定位真实有问题的原句，记录镜头／资产、原文位置、问题及必须保留的主体、动作、数量、方向、否定、条件和确定程度。区分语言歧义、设计缺口与事实冲突：有已知依据才消解歧义，缺口保留未知，冲突指出不能同时成立的要求，不替用户选方案。此步不输出替换句；无问题原样保留。
2. **删水分。** 按镜头目的保留识别、动作执行和连续性所需内容，仅删除没有独立信息的套话、重复铺垫与总结。背景次要不等于可删其事实；用于区分人物或保证单条 Prompt 独立可用的重复也须保留。风格、神情强度、数量、范围、比较、条件、否定、来源性质及必要摄影术语均属信息，不因“像模板”删除，不补画质词凑长度。
3. **改骨架。** 动作靠近主体，方向、程度和条件靠近作用对象；同一人物的姿态、持物、视线集中，交接或换主语处明确执行者。按视觉重点组织自然段，让环境承接主体，不串接维度。用已知具体动作替换抽象词，如“右手对白瓷杯进行握持”改为“右手握着白瓷杯”；依据不足则保留概括或记录缺口，不把“表达关心”补成“伸手拍肩”。拆长句不拆散关系，不添加因果或先后，不把静帧变成连续事件。
4. **反向查残。** 通读并逐项对照基线，查新增、遗漏、关系错接、含混指代、套句、无信息收尾及确定程度变化，尤其保留“仅、仍、才、若、约、轻微”等限制。用下表检查要求是否相容，通顺不等于等义。只处理能定位的问题；“像 AI”不是改写理由，不为人味添加经历、感想或事实。核对完成后进入既有硬校验、独立语义核对和冻结流程，评分不触发再润色。

| 关系 | 核对问题 |
|---|---|
| 主体与动作 | 移动、注视、持物、支撑和接触分别属于谁？代词或修饰语能否被误接到另一人或物件？ |
| 空间与方向 | 人物自身左右、当前画面左右与场景固定方位是否分清？换机位只改变投影关系，不搬门窗或交换持物手；依据不足不猜坐标。 |
| 动作与可见范围 | 关键手部、接触点与道具是否处于取景内，是否被身体或前景挡住？完整入画与裁切要求是否冲突？ |
| 摄影与清晰范围 | 景别、观察方向、焦点和必要清晰范围是否协调？不能用一个焦距或光圈数值保证不同距离对象都清楚。 |
| 光线与材质 | 必须读清的表情、接触与纹理是否有相容的光向和明暗条件？质感词不能替代具体可见依据。 |

只查本镜适用关系，不新增固定字段、正文段落或评分项。若解决问题需要改动作、布局或拍法，将方案作为导演补全另列；用户锁定的冲突保留待处理。

## 适合 Prompt 的表达

- 按“谁／什么，在什么位置，呈现什么动作或状态”组织句子，尽量用直接动词。长定语妨碍理解时拆开，不能拆散物件与人物的对应关系。
- 先交代本镜视觉重点，再让后句承接前句。默认用清楚、简短的自然段，每段围绕一个画面重点；只有信息确实并列、有顺序或需要比较时才用列表，不把正文排成字段清单或多层提纲。Excel 表格结构与内部检查项照常保留。
- 把已有的可见细节说清楚；只有“高级、电影感、富有感染力”而没有依据时，不凭空补上灯位、表情或材质。需要新增设计时作为导演提案另行说明。
- 内部保留角色名称与稳定 ID；模型正文按[人物指代规则](prompt-language.md#人物指代内部身份与模型正文)使用真实图片引用或必要可见特征，不把专名当成模型认识的身份。可以保留“妈妈／儿子”等有意义的角色称呼，避免“她／对方／该人物”的歧义。完整人设留在资产与三视图，不整套复制；实际没有身份图时不能写“沿用参考图”冒充就绪。
- 不把制作 Prompt 改成随笔、口号或聊天：不添加作者感想、第一人称经历、情绪化旁白。静帧保持一个确定时刻，不用“接着／随后／逐渐”扩成连续动作。
- 参数和技术术语可自然保留英文。画幅、分辨率与接口配置内部管理，摄影要求自然写入新版正文；不把 JSON 字段名、机器 ID 或配置对象当作画面语言，不增加自动词语替换或“人味分”。
- “值得注意的是”“总而言之”、设问自答、“不是X而是Y”、空泛程度词和生造术语仅作为检查线索；没有提供新信息时删除，有真实强调、比较或限制作用时保留含义。用普通词和准确动词说明关系，不把截图中的英语例词做成全局禁词表。写法截图只指导表达，不提供剧情、人物或场景事实。

下面是独立教学例句，不来自用户项目；“小林”是内部角色名称。它们只展示局部语言处理，不能当作经用户确认的优质基线；最终正文仍须用实际图片引用或必要可见人物描述，不能仅凭已登记名字直接提交。

| 字段 | 改写前 | 改写后 |
|---|---|---|
| 镜头内容 | 小林站立于柜台右侧的位置，右手对一只白瓷杯进行握持，视线被投向画面左侧的门口。 | 小林站在柜台右侧，右手握着一只白瓷杯，看向画面左侧的门口。 |
| 姿态与表情 | 小林的双肩呈现出放松的状态，下巴保持微抬的状态，嘴角带有轻微上扬的弧度。 | 小林双肩放松，下巴微抬，嘴角略微上扬。 |
| 光影／色调 | 在窗户位于画面左侧的情况下，建议使用柔和的窗光对小林左脸进行照明，窗户实际位置仍有待确认。 | 若窗户在画面左侧，建议用柔和窗光照亮小林左脸；窗户实际位置待确认。 |

第一例保留柜台右侧、右手、白瓷杯、视线及画面左侧门口；第二例保留同一时刻的三个姿态信息；第三例仍是有条件的布光建议。不能仅以字数减少或模型自评分判断改写成功。

另两例只展示何时不能直接改写，不是项目事实或固定镜头模板：

- **信息不足**：“两人站在门边，他把伞递给她。”若身份与持物依据缺失，指出递出者、接收者尚不明确；不擅自补性别、左右手或谁站门内。
- **要求冲突**：“只取眼睛至下巴的面部特写，同时完整拍到腰间双手。”保留两项要求并指出取景冲突；扩大景别属于拍法变更，不能作为等义润色静默执行。

## 摄影约束：焦距、光圈与对焦

`camera` 负责景别、机位和裁切边界；独立 `optics` 负责焦距、光圈、焦点及清晰范围。每镜先确定必须看清的人脸、手或道具和景层，再选参数，不能填完数值再改变画面事实来迁就。

- 焦距用 mm，光圈用 f/值（如 50mm、f/4），二者分别记录。用户已有要求优先；未给定时由 Agent 主动提出一套与画面协调的导演建议，不逐镜追问。画幅未知时明确以全画幅视角作为设计基准，不声称掌握真实机身、镜头或现场参数。
- 写明对焦对象及允许虚化的范围，必要时交代人物和物件是否处于相近距离。多人前后错开时不能只凭 f/值保证同时清晰；机距、主体距离未知就保留条件，不编造精确米数。
- 数值与可见要求一起进入自然正文，例如“以全画幅视角设计，50mm、f/4，对焦人物脸部和近旁握杯的右手，背景轻微虚化”。这只是写法例句，不是所有镜头默认参数；导演建议的依据记入 `designNotes`。
- 有角色或场景参考时仍明确本镜拍法、焦点和所需景深，不自动继承参考机位，也不因省略外貌/布景而省略摄影约束。换焦距、机位或景深时核对取景、轴线和关键物件可见性。
- 快门、帧率、ISO、设备等只在本次画面确有需求和依据时补充，不机械填写全套曝光表。静帧不强填采集帧率；没有照度和实际器材时不声称得到正确曝光。
- 目标模型有原生摄影参数时按实际接口映射；只有文本能力时保留镜头意图及清晰范围，不承诺模型物理执行精确。若接口映射改变已冻结正文，须形成新版本并核对，不在提交时偷偷换词。

## 人物指代：内部身份与模型正文

先按每个入镜人物的 `assetId` 查实际图片绑定，再决定正文称呼；不是全片统一选择有图或无图模式。名字和 ID 仍留在内部资产、原稿及连续性记录中，不对原稿做替换。

- **有可用角色图**：实际图像可访问、用途确为该角色，且 `subjects[].referenceIds` 指向对应已确认图片时，正文用该图的真实引用。确认来源按[资产先行流程](visual-workflow.md#0-可调整的完整-prompt-与分阶段出图默认流程)；只有文字档案、资产 ID、待生成三视图、未确认生成图或风格图不算角色图，缺失、错绑或不可读的图片不能伪装成已就绪。
- **没有角色图**：不用“林青”“陈舟”等专名代替身份说明，也不只写“人物A/B”。从本次已确定的可见特征中选简短、互不混淆的称呼，例如“穿灰色衬衫的人”和“穿深蓝色外套的人”；首次交代必要特征，后续可简写为“灰衬衫的人”和“深蓝外套的人”。“妈妈／儿子”等有实际剧情意义的称呼可以保留，同时交代必要可见特征；不靠亲属称呼锁定长相。
- **多人及跨镜**：逐人保持称呼与稳定资产 ID 的映射，持物、左右手、视线均落到具体人物。画面左右随机位改变，不作为唯一身份依据；换装时更新可见称呼并核对连续性，不能把前镜旧衣服带入本镜。有图、无图人物可在同一镜混用各自方式。
- **信息不足**：仅从已有事实或本次授权的虚构导演设计补足区分依据；不因要区分人物而虚构年龄、性别、面孔或参考。本次未授权且关键身份确实无法表达时，列出具体缺口，不写假引用。文字锚点能明确行为归属，不等于锁定跨图面孔。

冻结前逐人核对“内部资产 → 实际图片引用或可见称呼 → 动作与持物”，确认正文能脱离角色名单被理解。该检查由创作 Agent 完成；CLI 的 ID、哈希校验不代替语义判断，不增加用户逐镜确认步骤。只修改已授权的新稿或定向修订版本，不机械改写旧项目。导出与未来提交继续使用同一份冻结正文；执行时将真实引用映射为接口支持的图片输入，不额外拼回人名或整套人设。

## 已有确定参考图时

- 角色或场景已有用户确定的参考图，直接以实际图片的 `@` 引用定位，省略图中已确定的外貌、服装、固定布景及材质，不再输出单独的人物/场景描述段。仅有某类参考时只省略对应部分，无参考对象仍需必要描述；风格图不能当身份或场景图。
- 保留每个人的动作、姿态、神情、夸张程度、视线、持物与关系，以及本镜必要的机位、构图和清晰范围。参考中的中性表情不能覆盖剧本要求的怒吼、惊讶等表演。
- 剧本要求换装、门窗开闭、道具移动、布景或光影变化时，写清相对参考的具体差异及本镜状态，其他能省略的尽量省略；不重新铺陈整个角色或场景。参考未覆盖且本镜必需的信息，按事实或本次明确设计补充。
- 内部保留角色/场景档案、稳定 ID 和真实绑定；`subjects[].referenceIds` 定位角色参考，`shotSchema.referenceIds` 可记录本镜场景参考，参考的 `purpose` 写明用途及对应资产。`appearance/scene` 可记“采用已确认参考，仅变化为……”，对用户的描述栏也只展示引用与差异，不强填整套设定；`optics` 的摄影要求继续保留。
- 正文引用须与内部实际图片一一对应，并采用目标模型支持的标记和图片输入。示例名 `@角色图` 不是可提交的空占位符；目标接口未确定时保留真实附件名/节点绑定，执行时映射精确标记，不靠纯文本 `@` 冒充传图。
- 评分核对引用、用途、差异和连续性，不因没复述图中外貌/布景扣分；神情和夸张表演遗漏仍按对应维度扣分。无参考分支不受本节精简规则影响。
